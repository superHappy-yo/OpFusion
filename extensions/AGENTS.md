# extensions：插件开发 AI 规则

先读根 AGENTS、本目录 README、`modules/contracts/extensions.md`、相关公共契约和目标插件已有说明。本目录用于扩展，不授予整个仓库的写权限。当前只有规格，不能声称插件发现、加载或设备运行已经实现。

## 默认修改范围

- 开始前声明扩展类别、plugin_id、所需公共接口、支持矩阵和验收条件。使用 `docs/ai/extension-task.md`，将允许修改范围缩小到一个明确的插件目录。
- 默认只写获授权的 `extensions/<category>/<plugin_id>/` 内的清单、实现、测试、说明和 proposals。不得修改兄弟插件、核心模块、apps、公共契约、根依赖/构建/CI 或本目录公共说明。
- 任何位置的 AGENTS.md、CLAUDE.md、范围或所有权策略均受保护；新建插件不自动授权新建或改写治理提示词，可继承本文件。不得改规则来允许自己越界。
- 读取公开契约和其他插件清单用于判断兼容性不等于获得写权限。插件依赖通过声明的 provider ID 和版本解析，不导入其他插件的内部实现。
- 用户明确授权多个插件或公共契约变更时，按集成任务列出每个路径；不重复索取已提供的授权，不把范围扩张成全仓。

## 如何实现扩展

- 使用 contracts 的公开 C++ 类型和小型端口接口实现行为，以不可变记录表达数据；优先组合，不创建要求所有算子或设备继承的庞大万能基类。
- 插件不导入 frontend、fusion、planner、codegen、runtime、apps 或 backends 的具体实现。通过注入端口复用已有能力；第三方依赖必须声明，不能借机修改根依赖配置。
- 在自己的 plugin.toml 声明贡献，不要求修改中央列表或在核心增加按算子名/设备型号判断的分支。
- 清单解析与 provider 加载分开。禁止在库加载或静态初始化时硬件探测、测量、连接网络或向进程级全局可变 registry 自注册。
- 同一插件可以包含算子语义、前端绑定、参考方案和目标 lowering 等相关贡献；通过命名接口协作，不把缺失能力藏进影子字段。
- 算子必须明确语义版本、属性、shape/dtype、广播/归约和副作用；未知特征保守处理。前端映射须限制来源 domain/opset，不能按名称猜语义。
- 新设备先判断能否复用已有编译和执行 provider。已支持架构的新型号可采用数据扩展；新执行架构必须补实际适配，不能仅凭算力/带宽配置宣称可执行。
- discovered、清单有效、支持某工作负载、编译成功、数值验证通过与性能测量分别报告。发现成功不能自动登记 verified 候选；未知成本不是零。
- 保持区域接口和资源约束，不隐藏跨设备回退、额外调优或预算消耗。实际不支持时返回结构化原因。

## 契约不足与验证

- 若已有契约无法表达新语义、执行状态或资源机制，在本插件 proposals 中写最小变更及消费者影响；继续不依赖它的工作，不复制公共类型或修改邻居绕过边界。
- 新算子应有正常、边界、非法输入及参考数值检查；新设备应有识别冲突、依赖版本、支持条件与资源报告检查。
- 验证仅增加插件即可被发现，重复 ID/冲突不会静默覆盖，核心文件无需改动。没有加载器时这些是待实现验收，不虚构测试命令或通过结果。
- 完成前检查全部 diff、未跟踪文件、删除和重命名两端均在 allowlist 中。分别报告实际检查、模拟证据、实机证据和未验证范围。
