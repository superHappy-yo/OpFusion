# codegen：模块 AI 规则

本文件补充根 `AGENTS.md`。开始任务前先读根规则、本模块 README 和 `modules/contracts/candidates-costs.md`、`modules/contracts/backend-ports.md`、`modules/contracts/execution-plan.md`。

## 职责与边界

- 你负责：在固定区域、设备、接口和预算下搜索内部计算/存储/内核结构，通过注入的后端和测量端口形成候选。
- 默认可写：`modules/codegen/` 中与任务有关的实现、`tests/`、README、`docs/` 和 `proposals/`。
- 默认只读：其他模块、`apps/`、全局配置及治理文件。公共 contracts 规格与类型也只读。
- 所有 `AGENTS.md`、`CLAUDE.md`、范围/所有权策略即使在本目录也受保护；不得用修改规则来扩大当前任务。
- 禁止更改区域成员、输出集合、边界布局、事件政策或全局映射；不直接写候选快照和正在使用的计划。
- 导入边界：仅依赖 contracts 的公开类型和端口；其他能力由 apps 注入。禁止导入邻居模块的具体实现。

## 输入与交付

- 输入：TuningRequest、参考程序、后端/测量端口。
- 输出：TuningResult、新实现、验证和完整成本记录或失败原因。
- 贯穿例子：对 R123 优化 tile、循环或内核组织；若要改变边界，返回新接口提案而不是覆写原 iid。
- 公共接口不足时先写本模块 proposal；不要制造影子字段或修改邻居来适配自己。用户已授权的跨模块变更由集成任务明确拆分，不重复索要授权。

## 怎么实现与验证

- 当前没有业务代码。未来实现按实际任务放在本模块 `src/`，测试放在本模块 `tests/`；包名、依赖和真实命令由 M1 的集成任务建立，不能自行创造全仓构建体系。
- 先写明输入输出、失败语义和最小可验证行为；优先简单实现，不引入尚无使用场景的策略/基类。
- 重点验证：同 iid 替换仍核对数值、资源和时延；所有编译/测量成本计入预算；不将仅输出 Y 的程序替换要求 T1/Y 的接口。
- 完成前对照任务 allowlist 检查全部 diff、未跟踪文件及重命名两端；报告真实验证，不虚构硬件执行或测试通过。
