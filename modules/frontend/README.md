# frontend — 模型导入与语义规范化

状态：规格目录，尚无实现。修改前阅读本目录 [AGENTS.md](AGENTS.md)。

## 唯一责任

将外部模型转换为设备无关的 GraphSpec/TensorSpec，保存有序端口、轴含义和数值政策。

| 项目 | 契约 |
|---|---|
| 输入 | 模型文件/上游图、静态 shape、参数引用、数值政策 |
| 输出 | 规范化图、张量表、来源映射与诊断 |
| 允许依赖 | 仅依赖 contracts 的公开类型和端口；其他能力由 apps 注入。禁止导入邻居模块的具体实现。 |
| 不负责 | 禁止选择设备、执行融合搜索、预测时延、调用硬件或静默量化；不得丢弃外部消费者、复用端口或原始来源。 |

## 未来内部组织

按真实任务增加 `src/`、`tests/` 和 `docs/`；接口变更建议放 `proposals/`。目录是所有权边界，不要求独立发布包或独立服务。

将明确无偏置的 Conv、按通道 BiasAdd 和 ReLU 登记为三节点；前端 Conv 已带 bias 时避免再加一次。

## 验收重点

重复操作数 Add(U,U)、多输出/多消费者、缺 shape、未知算子、非法广播；规范化前后数值语义一致。

当前没有测试/启动命令。第一次实现时记录真实环境、命令与结果，不能把这里的验收目标写成已通过事实。

## 输入与扩展

首版 ONNX 模型包，后续按需增加 torch.export/StableHLO 前端；入口字段见 contracts/program-inputs.md。已有格式的新算子由 extensions 提供语义与版本化来源绑定，核心只消费注入目录。保存 source map 和 registry 身份，冻结研究图；导出成功不等于完整模型/设备支持。
