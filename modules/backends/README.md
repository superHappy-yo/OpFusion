# backends — 设备与编译执行适配

状态：规格目录，尚无实现。修改前阅读本目录 [AGENTS.md](AGENTS.md)。

## 唯一责任

组织能力查询、默认程序目录、编译/调用和设备操作的通用路由；具体设备、编译器、库和实现由独立扩展提供。

| 项目 | 契约 |
|---|---|
| 输入 | HardwareProfile、区域和接口、编译/执行/测量请求 |
| 输出 | 能力结果、默认实现、产物引用、资源和原始观测 |
| 允许依赖 | 仅依赖 contracts 的公开类型和端口；其他能力由 apps 注入。禁止导入邻居模块的具体实现。 |
| 不负责 | 禁止全图划分、分布式调度、修改代价标签或搜索任意区域；具体设备适配器不得依赖或修改其他设备适配器。 |

## 未来内部组织

按真实任务增加 `src/`、`tests/` 和 `docs/`；接口变更建议放 `proposals/`。目录是所有权边界，不要求独立发布包或独立服务。

只输出 Y 的融合实现可用于无外部分支的 R123；外部还需要 T1 时必须支持双输出或拒绝。

## 验收重点

支持条件与真实后端一致；包含 shape/dtype/layout/数值模式；失败不冒充不支持；产物版本和设备匹配；编译与原始时间记录可追溯。

当前没有测试/启动命令。第一次实现时记录真实环境、命令与结果，不能把这里的验收目标写成已通过事实。

## 新设备接入

先通过扩展协议接入一个 CPU 参考实现，再加入真实可用的 GPU。新增设备、编译器和实现进入 `extensions/` 的授权包；backends 内部按通用编译机制与设备执行机制组织，避免把一个编译器绑定为一个设备子类。不为未来 NPU/FPGA 填充虚假程序或性能。

后端负责把已选结构翻译/编译/执行为目标程序；codegen 决定搜索哪些结构。后端默认库选择可以作为固定且版本化的实现来源，但不能隐藏额外调优预算。

新型号若已有工具链/驱动覆盖，可只提供描述和匹配规则；新架构需要真实适配。支持判断以区域、接口、shape/dtype/layout、数值政策及软件版本为条件，不按设备名字分支。测量服务归 runtime，设备计时与同步原语由本模块组织。
