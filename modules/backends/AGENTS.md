# backends：模块 AI 规则

本文件补充根 `AGENTS.md`。开始任务前先读根规则、本模块 README 和 `modules/contracts/backend-ports.md`、`modules/contracts/candidates-costs.md`、`modules/contracts/worker-protocol.md`。

## 职责与边界

- 你负责：封装真实设备/SDK 的能力、默认程序、编译/调用、转换/复制原语和原始资源观测。
- 默认可写：`modules/backends/` 中与任务有关的实现、`tests/`、README、`docs/` 和 `proposals/`。
- 默认只读：其他模块、`apps/`、全局配置及治理文件。公共 contracts 规格与类型也只读。
- 所有 `AGENTS.md`、`CLAUDE.md`、范围/所有权策略即使在本目录也受保护；不得用修改规则来扩大当前任务。
- 禁止全图划分、分布式调度、修改代价标签或搜索任意区域；具体设备适配器不得依赖或修改其他设备适配器。
- 导入边界：仅依赖 contracts 的公开类型和端口；其他能力由 apps 注入。禁止导入邻居模块的具体实现。

## 输入与交付

- 输入：HardwareProfile、区域和接口、编译/执行/测量请求。
- 输出：能力结果、默认实现、产物引用、资源和原始观测。
- 贯穿例子：只输出 Y 的融合实现可用于无外部分支的 R123；外部还需要 T1 时必须支持双输出或拒绝。
- 公共接口不足时先写本模块 proposal；不要制造影子字段或修改邻居来适配自己。用户已授权的跨模块变更由集成任务明确拆分，不重复索要授权。

## 怎么实现与验证

- 当前没有业务代码。未来实现按实际任务放在本模块 `src/`，测试放在本模块 `tests/`；包名、依赖和真实命令由 M1 的集成任务建立，不能自行创造全仓构建体系。
- 先写明输入输出、失败语义和最小可验证行为；优先简单实现，不引入尚无使用场景的策略/基类。
- 重点验证：支持条件与真实后端一致；包含 shape/dtype/layout/数值模式；失败不冒充不支持；产物版本和设备匹配；编译与原始时间记录可追溯。
- 完成前对照任务 allowlist 检查全部 diff、未跟踪文件及重命名两端；报告真实验证，不虚构硬件执行或测试通过。
