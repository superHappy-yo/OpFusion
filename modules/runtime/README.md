# runtime — 协调端、工作端与执行状态

状态：规格目录，尚无实现。修改前阅读本目录 [AGENTS.md](AGENTS.md)。

## 唯一责任

按已验证的固定计划协调 worker，管理真实执行、产物、传输、事件和缓冲的生命周期。

| 项目 | 契约 |
|---|---|
| 输入 | ExecutionPlan、ArtifactRef、部署配置、后端执行端口 |
| 输出 | ExecutionReport、任务/传输事件和原始 MeasurementRecord |
| 允许依赖 | 仅依赖 contracts 的公开类型和端口；其他能力由 apps 注入。禁止导入邻居模块的具体实现。 |
| 不负责 | 禁止内部调用 planner/fusion/codegen 偷换计划；不得信任过期 attempt 事件或将断连视为成功；不承诺恰好一次执行。 |

## 验收重点

重复提交、状态迁移、过期事件、取消、断连、worker 故障、资源释放、产物 digest/版本不匹配；控制消息与张量数据分离。

当前没有测试/启动命令。第一次实现时记录真实环境、命令与结果，不能把这里的验收目标写成已通过事实。

## 内部职责（尚未建实现目录）

- Coordinator：计划接纳、worker 状态、分派、事件收集和终态汇总。
- Worker：验证 plan/attempt/产物，申请本地资源并通过注入的后端执行。
- Transport：控制消息与数据移动协议；网络传输属于这里，设备内复制/转换原语由 backend 提供。
- Artifact store：保存/获取按摘要引用的编译产物及原始记录，不在控制消息中发送张量本体。

这些职责属于一个 runtime 模块。首版单协调端；worker 断连或终态未知时向 apps 返回状态，不能自动引入新的映射或隐式跨设备续跑。
