# experiments — 实验协议与证据评估

状态：规格目录，尚无实现。修改前阅读本目录 [AGENTS.md](AGENTS.md)。

## 唯一责任

定义测量/正确性/基线协议，组织实验并从不可变原始记录评估排序、regret、容量和端到端效果。

| 项目 | 契约 |
|---|---|
| 输入 | 实验配置、公共 API、原始运行记录、明确的数据划分 |
| 输出 | 协议、带来源报告、原始记录引用和分析结果 |
| 允许依赖 | 仅允许 contracts 与 apps 的公开实验入口；算法独立评测经 apps 注入或调用，禁止直接导入其他模块；包括 apps 在内的生产模块不得依赖 experiments。 |
| 不负责 | 禁止改生产模块以制造收益、伪造/覆盖原始样本、泄漏测试标签、静默改基线预算或数值容差；生产模块不得依赖本模块。 |

## 未来内部组织

按真实任务增加 `src/`、`tests/` 和 `docs/`；接口变更建议放 `proposals/`。C++ 实现可复用的实验协议与算法逻辑；Python 仅用于测试驱动、测试数据、独立参考和测试结果核对，不承担生产/调优编排，也不另建一套被测核心算法供生产使用。目录是所有权边界，不要求独立发布包或独立服务。

分别比较未融合与合法融合，640/128 KiB 只是限定交接流量核算，不能作为 DRAM 或性能实测。

## 验收重点

重复测量与时延边界；图/shape/设备留出；模拟与实机区分；固定候选、实现、调优预算与调度器；报告失败和缺失。

当前没有测试/启动命令。第一次实现时记录真实环境、命令与结果，不能把这里的验收目标写成已通过事实。
