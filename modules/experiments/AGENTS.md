# experiments：模块 AI 规则

本文件补充根 `AGENTS.md`。开始任务前先读根规则、本模块 README 和 `modules/contracts/candidates-costs.md`、`modules/contracts/execution-plan.md`、`modules/contracts/worker-protocol.md`。

## 职责与边界

- 你负责：定义测量/正确性/基线协议，组织实验并从不可变原始记录评估排序、regret、容量和端到端效果。
- 默认可写：`modules/experiments/` 中与任务有关的实现、`tests/`、README、`docs/` 和 `proposals/`。
- 默认只读：其他模块、`apps/`、全局配置及治理文件。公共 contracts 规格与类型也只读。
- 所有 `AGENTS.md`、`CLAUDE.md`、范围/所有权策略即使在本目录也受保护；不得用修改规则来扩大当前任务。
- 禁止改生产模块以制造收益、伪造/覆盖原始样本、泄漏测试标签、静默改基线预算或数值容差；生产模块不得依赖本模块。
- 导入边界：仅允许 contracts 与 apps 的公开实验入口；算法独立评测经 apps 注入或调用，禁止直接导入其他模块；包括 apps 在内的生产模块不得依赖 experiments。

## 输入与交付

- 输入：实验配置、公共 API、原始运行记录、明确的数据划分。
- 输出：协议、带来源报告、原始记录引用和分析结果。
- 贯穿例子：分别比较未融合与合法融合，640/128 KiB 只是限定交接流量核算，不能作为 DRAM 或性能实测。
- 公共接口不足时先写本模块 proposal；不要制造影子字段或修改邻居来适配自己。用户已授权的跨模块变更由集成任务明确拆分，不重复索要授权。

## 怎么实现与验证

- 当前没有业务代码。未来实现按实际任务放在本模块 `src/`，测试放在本模块 `tests/`；包名、依赖和真实命令由 M1 的集成任务建立，不能自行创造全仓构建体系。
- 先写明输入输出、失败语义和最小可验证行为；优先简单实现，不引入尚无使用场景的策略/基类。
- 可复用协议与算法逻辑使用 C++；Python 仅用于测试驱动、数据、独立参考和结果核对，不承担生产/调优编排，生产模块不得依赖 Python 测试代码。
- 重点验证：重复测量与时延边界；图/shape/设备留出；模拟与实机区分；固定候选、实现、调优预算与调度器；报告失败和缺失。
- 完成前对照任务 allowlist 检查全部 diff、未跟踪文件及重命名两端；报告真实验证，不虚构硬件执行或测试通过。
