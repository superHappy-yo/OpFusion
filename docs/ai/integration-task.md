# 跨模块集成任务提示词模板

集成任务负责跨模块协作和系统验收。它不会自动取得全仓修改权限；必须明确本次允许的路径。当前仓库的文档初始化属于用户已明确授权的 bootstrap，可覆盖初始化所需目录；这个授权不会自动延续为未来每个模块任务的全仓权限。

```text
任务：<跨模块目标>
授权依据：<用户本次指令或持续有效的明确授权>
允许修改：<逐项列出模块、apps 和必要共享文件的范围>
本次只读/禁止修改：<仍受保护的路径>
相关契约与版本：<当前版本和计划变化>
集成验收：<完整输入、预期输出、失败及资源/数值条件>

先读根 AGENTS.md、docs/ai/scopes.json、所有涉及模块的说明和相关公共契约。
将任务拆成范围不重叠或已有明确交接顺序的子任务。
每个子任务必须包含目标、只读契约、允许写入路径及验收条件。
子代理不能自行扩展范围；集成代理也不能通过分派任务绕过根规则。

公共契约变化按 docs/ai/contract-change.md 推进。
已获用户授权的跨模块范围直接执行，不重复请求确认。
如发现必须扩大的范围，先完成独立部分，再给出具体差异和所需授权；不要笼统要求重批整个任务。

各模块只使用公开接口；具体实现选择、依赖注入与流程装配放在 apps/。
不通过跨模块私有导入或相互回调修补循环依赖。
保持候选、契约、实现和代价快照的版本一致；反馈更新进入后续轮次。

收集子任务结果，检查范围、接口、版本、数值与资源语义。
在已存在的验证入口下执行组合检查；明确未运行、模拟和实测的差别。
最终报告各模块变更、公共契约变化、验证证据、已知限制与回退路径。
```

## 子任务分工表

| 子任务 | 允许写入 | 只读输入 | 交付给谁 |
|---|---|---|---|
| 契约变更 | 授权的 `modules/contracts/` 规格、样例与测试 | 现有生产者/消费者接口 | 相关模块 |
| 生产者适配 | 生产者模块授权路径 | 已确定的契约 | 集成任务 |
| 消费者适配 | 消费者模块授权路径 | 同一契约 | 集成任务 |
| 装配与组合验证 | 明确授权的 `apps/` 及验证路径 | 各模块公开入口 | 用户 |

表中的路径仅描述角色，不替代本次任务的实际白名单。治理文件和根依赖/CI 配置如需修改，必须单独列入授权范围。

## 集成必须保持的系统边界

- `contracts` 描述公共数据与端口，不能反向依赖算法或运行时实现。
- `fusion` 决定候选区域与保留结果；`planner` 决定设备映射和事件计划；`codegen` 在固定边界下优化程序。
- `runtime` 执行已选择的计划并产生事实记录，不自行改写融合语义或静默替换候选。
- 设备能力、编译和执行由 `backends` 适配，算法层不硬编码特定 SDK 的内部对象。
- `experiments` 组织评测与证据，不成为生产模块依赖的运行时服务。
- `apps/` 连接各端口和实现，负责一轮轮推进优化与执行；反馈是版本化数据，不构成双向模块依赖。

## 并行工作规则

同一文件只分配一个写入任务。需要并行修改同一公共契约时，先合并为一个契约维护任务，其余任务只读。发现其他协作者的改动时保留，不通过重置工作区或覆盖文件消除冲突。

分支或 worktree 可降低文件冲突，但本身不提供目录级写入权限。真正的执行隔离与合并检查见 [enforcement.md](enforcement.md)。
