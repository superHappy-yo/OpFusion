# 单模块任务提示词模板

将下列内容放入任务正文或聊天，替换占位符。无需为了使用模板而新增任务文件。模板本身不授予权限，实际范围以用户授权、根规则和范围登记表为依据。

```text
任务：<需要解决的具体问题>
所属模块：<contracts/frontend/backends/cost_model/fusion/planner/codegen/runtime/experiments>

先阅读根 AGENTS.md、docs/ai/scopes.json、目标模块 AGENTS.md 和 README.md。
只读依赖：<相关公共契约、架构说明、其他模块公开接口>
允许修改：<明确的仓库相对路径，优先列具体文件或本模块子目录>
目标行为：<输入、输出及异常条件>
验收条件：<可检查的行为、需要的测试或文档核查>
公共契约影响：<无，或已有授权的契约变更任务标识>

遵守以下边界：
- 默认不修改其他模块、apps、公共契约、根依赖/构建/CI 配置。
- 所有 AGENTS.md、CLAUDE.md 和 docs/ai/scopes.json 默认只读。
- contracts 模块任务仅可修改明确授权的契约规格、类型/端口实现、纯不变量校验和契约测试，不可借机修改治理文件。
- 不复制公共类型，不依赖其他模块私有实现，不新增隐式全局状态或双向依赖。
- 不把测试夹具的理想值、预测值或模拟值描述为真实设备测量。
- 不顺便清理、格式化或重构授权范围外的文件。

执行前简述拟修改文件、采用的已有接口及验证方式。
如果依赖缺口阻塞实现，在本模块 proposals/ 下写最小变更建议，继续可独立完成的工作。
若用户已授权相应跨模块范围，按集成任务分解执行，不重复请求同一授权。
完成后检查全部 diff、新文件、删除和重命名是否符合范围，并报告验证及残留问题。
```

## 使用示例：仅研究一的候选筛选

```text
任务：为 fusion 模块定义候选保留的输入输出与失败情况。
所属模块：fusion
只读依赖：modules/contracts/ 中现有候选、接口和代价契约；modules/cost_model/README.md。
允许修改：modules/fusion/README.md、modules/fusion/proposals/*.md。
目标行为：说明如何保留完整候选划分，以及预算耗尽时如何返回已有结果。
验收条件：不把局部最优说成全局最优；不改动 cost_model 或 planner；明确验证状态与代价来源。
公共契约影响：无；如发现字段不足，仅写 proposal。
```

该示例只授权文档，不授权实现算法、建立新公共类型或更改其他模块。

## 验收记录建议

| 项目 | 应记录内容 |
|---|---|
| 文件范围 | 实际修改路径与授权路径是否一致 |
| 依赖 | 是否仅使用公开契约和允许的依赖方向 |
| 行为 | 已实现、仅规格、模拟或待验证分别标记 |
| 验证 | 实际执行的检查及结果；未执行的原因 |
| 后续需求 | 所需契约变更或其他模块任务，附具体依据 |
