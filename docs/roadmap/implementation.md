# 实施路线与阶段验收

每阶段只承诺已经完成的证据。当前完成的是 M0 文档骨架；下面所有运行验收都尚未实现。

| 阶段 | 最小范围 | 通过条件 |
|---|---|---|
| M0：规格 | 模块、提示词、契约、任务模板 | 路径和依赖一致，Conv 示例与数值核算正确，仓库无伪业务入口 |
| M1：语义、扩展与工程门禁 | contracts＋frontend＋apps 发现器；集成任务建立 Python 工具链和路径/导入检查 | 规范化 ONNX Conv 为明确的三节点例子；Add(U,U) 保留两个端口；非法图被拒绝；只增加一个算子包即可识别且核心 diff 为空；重复/歧义/依赖冲突失败；越界改动测试能失败 |
| M2：可执行参考 | 一个 CPU 扩展＋backends 通用路由＋runtime 本地 worker＋apps | 完整参考图实际运行，输出通过规定数值测试；记录真实版本、计时、内存和事件；无输入/参数漏计；验证/测量复用 runtime 生命周期 |
| M3：研究一最小闭环 | cost_model＋fusion；复用已登记实现 | 输出未融合及合法融合候选；保留外部结果；预测与实测分开；固定候选/预算评估排序和 regret |
| M4：单机异构规划 | planner＋一个 GPU 扩展＋已有运行时 | 输入驻留与输出目标会改变计划；包含转换/复制；容量不足、接口不兼容有拒绝理由；新型号复用已有 provider；缺 GPU 依赖不阻断无关语义/CPU 贡献；实机执行计划 |
| M5：跨主机运行 | runtime Coordinator/Worker/transport＋apps | 首先确定 RPC ADR；两个真实主机 worker 完成计划；校验重复请求、过期事件、断连、取消和产物不匹配；不得把单进程模拟称分布式执行 |
| M6：研究三 | codegen＋生成/编译扩展；TVM 路线优先 PoC，按需 Triton 对照 | 同一区域/设备/接口下生成新实现；有 oracle 时无种子探索也能启动；独立 implementation 包给旧算子增加目标支持；记录全部搜索成本；版本替换重新检查全图数值、容量和端到端效果 |
| M7：研究评估 | experiments＋稳定公开 API | 固定候选池、预算和调度器；消融区分建模/搜索/后端收益；留出图/shape/设备与校准标签隔离 |

M1 的治理检查是明确授权的集成任务，不能由某个模块代理擅自改根配置完成。当前没有实际 CI 工作流、必需检查或分支保护；将来开启时需要真实验证成功与故意越界失败两条路径。

M1 首次建立通用发现器/语义端口后，普通扩展任务只修改授权插件目录。M6 的工具链小规模 PoC 可提前独立进行，不必等待跨主机实现；PoC 采用固定区域、固定接口及已知参考路径，不借机接管全图融合和调度。具体生成后端通过 PoC 后才锁定依赖版本。

先使用小而确定的算子族。Conv 示例只作为一致性和端到端贯穿用例，不能替代性能泛化证据。NPU、FPGA、动态 shape、跨区域 tile 流水、任意算子裂变和高可用服务不进入首个 MVP；有明确任务、后端与验证条件后再扩展。
